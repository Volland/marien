TOUR · KNOW YOUR CUSTOMER

Who really owns Orchid Capital?

A compliance team keeps people, companies and bank accounts in LadybugDB. This tour writes their checks as Marien rules and runs them. Every result below is what the LadybugDB __LBUG__ CLI printed for examples/kyc.

01

Load Marien and describe the graph

Load the extension by path, create Marien's module tables once, then define the schema in plain Cypher. Holds has two FROM/TO pairs: a person or a company can hold an account.

schema.cypher
LOAD EXTENSION './libmarien.lbug_extension';
CALL elpi_init();

CREATE NODE TABLE Person(id INT64 PRIMARY KEY, name STRING, country STRING,
                         pep BOOL, kyc_verified DATE);
CREATE NODE TABLE Company(id INT64 PRIMARY KEY, name STRING, country STRING);
CREATE NODE TABLE Account(iban STRING PRIMARY KEY, currency STRING);
CREATE REL TABLE ShareholderOf(FROM Person TO Company, share DOUBLE);
CREATE REL TABLE Owns(FROM Company TO Company, share DOUBLE);
CREATE REL TABLE Holds(FROM Company TO Account, FROM Person TO Account);
02

The schema becomes types

Marien turns every table into an ELPI kind with a constructor from its primary key, and every property into a predicate. Rules are checked against this signature; you never write it yourself.

lbug
CALL elpi_signature('Person') RETURN text;
textgenerated from the catalog
kind person type.
:index (2)
pred person o:person.
type person int -> person.
:index (2)
pred person.name o:person, o:string.
:index (2)
pred person.country o:person, o:string.
:index (2)
pred person.pep o:person, o:bool.
:index (2)
pred person.kyc_verified o:person, o:int.
type subj_person person -> subject.

person 7 is the person with key 7, and person P lists them all. A DATE is an int of days since 1970; a BOOL is tt or ff.

03

Write the checks as rules

One module, kyc, with four checks. A rule reports a violation with a severity, a code and the subject at fault. graph.std brings ready-made graph combinators such as transitive closure and cycle witnesses.

kyc.elpi
accumulate graph.std.

pred violation o:severity, o:string, o:subject.

% A shareholder with 25% or more whose KYC check was never completed.
violation error "unverified-ubo" (subj_person P) :-
  shareholder_of P E _, shareholder_of.share E S, S >= 25.0,
  not (person.kyc_verified P _).

% Companies that own each other in a circle hide who controls them.
violation error "circular-ownership" (subj_company C) :-
  acyclic_witness_in in_cycle.owns C.

% Every company needs at least one person behind it.
violation warning "no-ubo" (subj_company C) :-
  company C, not (ultimate_owner _ C).

% Accounts of politically exposed persons need enhanced due diligence.
violation warning "pep-account" (subj_account A) :-
  holds (holds.src.person P) _ (holds.dst.account A), person.pep P tt.

pred ultimate_owner o:person, o:company.
ultimate_owner P C :- shareholder_of P _ C.
ultimate_owner P C :- shareholder_of P _ D, closure (edge_of owns) D C.

pred ubo_of i:company, o:person.
ubo_of C P :- ultimate_owner P C.
lbug
CALL elpi_save('kyc', '…the module above…');
04

Validate the graph

elpi_validate runs every violation rule of the listed modules and returns one report. It is an ordinary table function, so the rows sort, filter and join like any other.

05

Ask typed questions

A predicate with modes is an entry point. elpi_run takes its i: arguments as parameters and returns its o: arguments as typed columns: a person comes back as its key, ready for a MATCH.

lbug
CALL elpi_run('kyc', 'ubo_of', {in1: 12})
WITH DISTINCT out2 MATCH (p:Person {id: out2})
RETURN p.name AS beneficial_owner ORDER BY beneficial_owner;

While writing rules, elpi_query takes any goal and returns its bindings as structured terms:

07

Mistakes stop at the door

A module is typechecked against the schema when it is saved. A misspelled property and a date compared with a string are both refused, with the module, line and column.

lbug
CALL elpi_save('typo', '… person.kyc_verifed P D, D < 20000.');
CALL elpi_save('typed', '… person.kyc_verified P D, D < "2025-01-01".');
refusednothing was stored
elpi_save typo: typo:2:47: undeclared constant 'person.kyc_verifed'
elpi_save typed: typed:2:76: "2025-01-01" has type string but is used with type int
08

Partition it for a big graph

A rule that only looks one step away from its subject can run in batches of subjects, each in a fresh store. Declare it, and Marien's locality check decides at save time whether that gives the same answer as full scope; if not, the save fails.

kyc_people.elpi
pred violation o:severity, o:string, o:subject.
violation error "unverified-ubo" (subj_person P) :-
  shareholder_of P E _, shareholder_of.share E S, S >= 25.0,
  not (person.kyc_verified P _).
% @marien partition violation by person radius 1
lbug
CALL elpi_partition_batch=2;   // two people per batch, to see it work
CALL elpi_validate(['kyc_people']) RETURN module, code, subject_pk;
1 rowtwo batches, one answer
modulecodesubject_pk
kyc_peopleunverified-ubo2
09

Rules that write rules

Annotate tables, and let a meta-rule read the schema and the annotations to generate checks. The generated clauses are typechecked and analysed like source, stored with the module, and rebuilt when the schema or an annotation changes.

kyc_meta.elpi
accumulate graph.std.
pred violation o:severity, o:string, o:subject.
% @marien meta
pred generate o:string.
generate S :- schema.annot T "acyclic" "true", schema.ident T R,
  schema.rel T K _, schema.ident K N,
  S is "violation error \"cycle\" (subj_" ^ N ^ " X) :- acyclic_witness (edge_of " ^ R ^ ") X.".
% @marien end
lbug
CALL elpi_annotate('Owns', 'acyclic', 'true');
CALL elpi_save('kyc_meta', '…');
MATCH (m:_elpi_module {name: 'kyc_meta'}) RETURN m.generated;

10

When the schema changes

Each module remembers a hash of the tables it reads. Drop a property it uses and the next run says so precisely, instead of quietly answering against a different schema; elpi_recheck records which modules broke. Modules that read nothing that changed stay ok.

lbug
ALTER TABLE Person DROP kyc_verified;
CALL elpi_validate(['kyc']) RETURN code;
